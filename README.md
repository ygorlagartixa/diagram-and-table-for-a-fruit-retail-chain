# 🎯 | Challenge  <a id="Challenge"></a>
This project was developed to model and simulate the database system of a fruit retail chain.
The main objective was to translate a comprehensive set of business rules into a structured, normalized, and robust conceptual (ER model) and logical (relational schema) database model.

# 💡 | Solution  <a id="Solution"></a>
In the real world, a database system with this architecture is essential for the operation of retail chains and supermarkets, enabling:
- **Operational and Workforce Management**: Monitor employee allocation across branches and manage corporate insurance policies.
- **Food Traceability and Logistics**: Track the exact origin of products (local, European, or exotic) while ensuring compliance with health certificates and distributor information.
- **Advanced Commercial Management**: Generate detailed invoices based on register number, date, time, and customer, while optimizing inventory management and relationships with multiple fruit suppliers.

Key Features and Entity Relationships:
- Fruit Store and Internal Resource Management.
- Fruit Specialization.
- Inventory control.
- Sales and Invoicing Management.
- Supply and Availability.

The main objective of the Entity-Relationship diagram (ER model) and the relational schema (logical model) was to translate the business rules of a fruit retail chain into a structured and normalized relational database.
The conceptual diagram visually maps the entities and their cardinalities, while the relational schema formally defines the tables, primary keys, foreign keys, and integrity constraints.
